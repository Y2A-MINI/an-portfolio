Case 01

Tamary

来店時の小さな迷いを減らし、会員情報・特典・QRを短い操作で扱える店舗体験へ。

Status
開発中
Scope
UX設計 / Figma / 実装設計 / 動作検証
Surface
Mobile web mock

01 / Challenge

店頭で、説明なしでも使えること。

残高、特典、履歴、会員QRなど、用途の異なる情報を小さな画面で迷わせず扱う必要がありました。

02 / Decision

今使う情報を、最初の画面に集約。

日常の確認と店頭アクションを分け、重要な情報ほど短い移動で到達できる構造に整理しました。

03 / Design

静かな画面に、必要な反応だけ。

役割ごとの画面と表示状態を揃え、QRの表示・非表示を含む操作を動くモックで検証できる形にしました。

設計を、判断できる動きにする。

静止画のレビューだけでは見落としやすい「どこを押し、何が変わるか」を動画で確認できる状態にしました。

  • 主要画面をまたぐ操作フローを実装
  • 会員・スタッフ画面の情報設計を統一
  • 会員QRの表示・非表示動作を検証

本案件は開発中です。公開用動画ではQR・会員IDなどの識別情報をマスクしています。外部サービス連携や本番公開を示すものではありません。

AN担当

要件整理、情報設計、Figma最終調整、実装方針・レビュー、操作モックの動作確認。AI／engineerによる実装を統括し、企画段階の要望を関係者が触れて判断できる状態へ変換しました。

Case 02

Dr.SHIN

靴の状態を写真から診断し、「何を使えばよいか」まで迷わず進める購買体験へ。

Status
本番稼働
Scope
UI/UX / Figma / Frontend / AI連携
Stack
Shopify / Fly.io / Claude API

01 / Challenge

汚れを見ても、正しいケアは分からない。

専門知識がない利用者でも、写真を起点に靴の状態と次の行動を理解できる必要がありました。

02 / Decision

診断と買い物を、一つの流れにする。

画像選択、AI診断、状態レベル、推奨商品を直線的につなぎ、結果の理解から商品選択までの迷いを減らしました。

03 / Delivery

Figmaから、本番の診断体験へ。

Fly.io上の診断アプリをShopify公開ページ内のiframeへ組み込み、Claude APIによる画像診断を接続して、実際に利用できる状態にしました。

Figma → working product

見た目の再現だけでなく、画像を選び、診断が走り、結果と推奨商品が返る一連の体験まで接続しています。

  • Shopifyの公開ページで診断フローが稼働
  • 実画像をClaude APIで解析し、状態を提示
  • 診断結果から関連商品へつながる導線を実装

掲載動画は2026年9月4日に、公開ページ上でテスト用画像を使って収録した動作確認です。

AN担当

体験設計、Figma UI v3の判断・調整、実装要件策定・レビュー、本番デプロイ・実ブラウザ検証。フロントエンドはAI／engineerと協働して実装し、診断機能だけでなく、利用者が結果を理解して商品を選べるところまで体験設計しました。

Working method

判断と実装を分断しない。

  1. 01

    Observe

    現場の利用場面と、利用者が迷う瞬間を捉える。

  2. 02

    Structure

    要件と情報を、優先順位のある画面構造へ変換する。

  3. 03

    Prototype

    Figmaと動くモックで、関係者が判断できる材料をつくる。

  4. 04

    Implement

    UIと実際のデータ・API・業務導線をつなぐ。

  5. 05

    Verify

    実機で操作し、期待した体験になっているかを確かめる。

曖昧な要望から、
使えるところまで。

企画、デザイン、実装の間にある翻訳を一つの流れで担い、判断できるものを早くつくります。
