Case 01

Tamary

会員情報、特典、履歴、会員QRを店舗で扱う会員アプリ。顧客・スタッフ双方の画面と操作フローを設計し、Web・Nativeの開発と検証を進めています。ここでは会員体験を確認するWebモックを掲載しています。

Status
開発・検証中
Scope
UX設計 / Figma / 実装設計 / 動作検証
Surface
Web / Native（掲載：Webモック）

Figma

会員ホームの代表画面。残高・特典・履歴・QRへの導線を一画面に整理しています。

Prototype

会員ホームからQR表示、履歴、メニューへ移動する操作を収録しています。

実装・検証事実

  1. 01主要画面をまたぐ操作フローを実装
  2. 02会員・スタッフ画面の情報設計を統一
  3. 03会員QRの表示・非表示動作を検証

掲載動画は会員体験を確認するためのモックです。QR・会員IDなどの識別情報をマスクしています。製品の外部サービス連携や本番公開を示すものではありません。

AN担当範囲

要件整理、情報設計、Figma最終調整、実装方針策定・レビュー、操作モックの動作確認を担当。

Case 03

KicksWrap 卸受注システム

注文受付、承認、注文管理、CSV出力をまとめたB2B業務アプリ。卸先と受注担当の業務を、役割に応じた画面と操作でつないでいます。

段階
本番導入・改善中
担当
業務設計 / 管理画面 / 実装・検証
対象
卸先・受注担当・管理者向けWebアプリ

取り組み

  1. 01卸先の注文入力から承認・注文管理までの業務フローを設計
  2. 02取引先、商品、価格、配送先を扱う管理画面を実装
  3. 03既存業務に合わせたCSV出力と移行時のデータ互換を検証

AN担当範囲

要件整理、業務フローと画面の設計、AIを活用した実装・レビュー、移行と本番導入の検証。

現在の段階

受注管理の本番導入を実施し、改善を継続。月次請求CSV・顧客向け納品書の追加機能は開発と検証を終え、本番反映と確認を残しています。

顧客・取引先情報、管理画面のアクセス先、実際の受注データは掲載していません。

Case 04

KicksWrap AIカスタマーサポート

問い合わせ受付、AIによる分類・返信案、注文確認をつなぐ顧客対応の仕組み。対応担当者が会話と返信状況を同じ窓口で確認できるように設計しています。

段階
本番導入・改善中
担当
対応フロー / 管理画面 / AI・注文連携
対象
問い合わせ窓口・CS管理画面

取り組み

  1. 01商品・ケア相談と、配送・返品・不良の問い合わせ導線を設計
  2. 02Shopifyの注文情報を使った返信案と、条件付き自動返信を実装
  3. 03同じ顧客の会話を一つの窓口へまとめ、人が確認・返信する運用を整備

AN担当範囲

顧客と対応担当者の体験設計、要件整理、AIと注文情報の連携方針、実装・検証、運用改善。

現在の段階

本番導入後も、返信内容、注文照合、例外を人へ渡す条件を改善しています。自動対応は対象条件を限定し、新しい機能の実運用での確認を続けています。

問い合わせ原文、顧客情報、返信の内部ルールや運用数値は非公開です。

公開ストアの改善案件です。未公開の運用データや管理画面は掲載していません。

Case 08

KicksWrap ストア導線分析・診断アプリ移行

診断の利用、商品提案、注文を同じ流れとして捉えるための調査と設計。どこで離脱し、どの商品が注文につながるかを確認できる計測基盤と、診断アプリの移行方針を検討しています。

段階
調査・計画段階
担当
導線調査 / 計測設計 / 診断移行計画
対象
ストア内の診断・商品提案・購入導線

取り組み

  1. 01本番テーマ、既存診断アプリ、注文の記録を照合
  2. 02診断利用と注文の部分的な観測を分け、現状の計測範囲を整理
  3. 03設問・回答・結果商品を保全する手順と、段階的な移行計画を作成

AN担当範囲

現況調査、導線・計測の設計、移行要件整理、検証計画と工数見積り。

現在の段階

現況調査と計画の段階です。移行対象、UIの変更範囲、データ保存と同意の条件を確認中で、移行実装・本番切替は未着手です。売上低下の原因や改善効果は未確定です。

調査・計画の事例です。売上・注文・顧客の個別データや、未確認の成果数値は掲載していません。
